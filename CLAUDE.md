# Вираж — тренажер маршрутів практичного іспиту ТСЦ

**Після відновлення сесії ПЕРШИМ ДІЛОМ читай `PROGRESS.md` і продовжуй з наступного кроку. Нічого не переробляй.**

## Що це
Статичний сайт + PWA (GitHub Pages): карта, маршрут іспиту, машинка їде маршрутом, підказки про знаки.
Зараз — ТСЦ № 6841 (Хмельницький), 20 маршрутів. Архітектура — під кілька ТСЦ.

## Правила
- Мова інтерфейсу, документації і комітів — українська.
- Контракт даних: `src/types.ts` + `docs/DATA.md`. Не міняти без запису в `docs/DECISIONS.md`.
- `tools/` і `data/` — пайплайн, тільки локально. У репо йдуть лише готові JSON у `public/data/` та `data/routes-src/*.yaml`.
- `data/raw/`, `data/cache/`, `data/osm/`, `data/preview/`, `ref/` — у `.gitignore`.
- Жодних ключів і секретів. Тільки безкоштовні сервіси без ключів.
- Атрибуція «© OpenStreetMap contributors» обов'язкова.
- Vite `base: '/virazh/'`, hash-роутинг, усі шляхи через `import.meta.env.BASE_URL`.
- Маленькі коміти + push після кожного маршруту / етапу.
- Рішення записувати в `docs/DECISIONS.md`. Маршрути, що не зійшлися, — у `docs/REVIEW.md` з `verified: false`.
- Оцифрування: максимум 3 спроби виправлення на маршрут, не вигадувати.

## Ліміт використання
- Перед кожним сабагентом і кожним маршрутом перевіряти ліміт (інструмент `get_usage`), записувати `node tools/usage-write.mjs`.
- ≥ 80% — не починати нову велику задачу; ≥ 85% — чекпоінт: оновити `PROGRESS.md` → commit → push → зупинитись.
- Не створювати завдань у Планувальнику і не запускати окремі процеси `claude`.

## Команди
- `npm run dev` / `npm run build` / `npm run typecheck`
- `npx tsx tools/build-route.ts 6841_1` — зібрати маршрут із YAML
- `npx tsx tools/preview-route.ts 6841_1` — PNG у `data/preview/`
- `npx tsx tools/build-index.ts` — перезібрати `centers.json` і `centers/*.json`
